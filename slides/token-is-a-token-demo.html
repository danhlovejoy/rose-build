A Token Is a Token

How Words and Pixels Both Become Vectors

A word has to be converted into numbers before a model can use it, while a patch of pixels is already a list of numbers; It's very easy to convert pixels into vectors, but words require an extra step.

1

Chop the input into pieces

A transformer never takes in a whole sentence or a whole image at once. It takes pieces. For text, a tokenizer splits the sentence into units from a fixed vocabulary, and a common word stays whole while an unusual one breaks into fragments, which is why “spreadsheet” in the sixth sentence below becomes three tokens. For an image, a vision transformer1 cuts the picture into a grid of square patches, and every patch is a token whether it holds the kitten’s ear or a stretch of blank sky.

The pieces are different kinds of things. A text token is a chunk of meaning, chosen so that frequent words stay intact and rare words split into reusable parts. An image patch is a chunk of space, chosen by position alone, and the cut pays no attention to what is in the picture, so an edge or an eye can land across a patch boundary. Try the patch size buttons. For the default image, 32-pixel patches give 77 tokens, 16-pixel patches give 308, and 8-pixel patches give 1,232, while the sentence keeps the same token count no matter what.

2

Turn each piece into numbers

Here the two sides differ. A text token is a string, and a string is not something you can multiply, so the model looks it up in a table with one row per vocabulary entry and 384 numbers per row, and that table was learned during training. The patch needs no table. Its pixels times three color channels are already a list of numbers (768 of them for a 16-pixel patch), and a vision transformer passes that list through one learned matrix to resize it to the model’s width.

3

What the model receives

Each strip below is a sequence of vectors drawn as columns, one column per token. The top strip came from the image and the bottom strip from the sentence, and by this point both inputs have become the same kind of object, a list of same-range numbers in order, which is why both kinds of transformer add a position embedding to every token before the first layer. Hover a column for its source.

Each column shows 48 evenly spaced values from its vector, standardized to mean 0 and spread 1 so the two strips share one color scale; a transformer’s layer normalization does something close to this to every token. The image columns hold raw patch values rescaled to −1 to +1, one step short of the learned resize a real ViT applies.

Where you will meet this again

In the NLP lab, model.encode() runs the tokenizer and the lookup table from Stage 2 before any attention layer, and in the CV lab MobileNetV2 skips the chopping step and reaches its vector by convolution. Start with the model card. The all-MiniLM-L6-v2 model card names the tokenizer and the 384-dimension output, the Hugging Face tokenizer summary explains WordPiece and its relatives, the Vision Transformer paper (Dosovitskiy et al., 2020) introduced the 16-by-16 patch as a token and its title is the one-line version of this page, and the embeddings demo picks up where this one stops, with what the 384 numbers encode.

Notes

  1. This page follows the vision transformer (ViT) route, not the CNN route. A CNN does not chop first. MobileNetV2, the model you used in the CV lab, slides small filters across the whole image and shrinks the result layer by layer until one vector remains, so there is no step where the image becomes a sequence of patches. Both routes end at a vector you can compare with cosine similarity, and only the transformer route passes through a sequence of tokens on the way. ↑ back
