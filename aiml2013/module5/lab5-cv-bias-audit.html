The Task

In the readings and in class, you learned that a model's overall accuracy can mask large disparities across subgroups. A face-attribute classifier that is 94% accurate overall might be 99% accurate on one subgroup and 65% accurate on another. The overall number looks good; the per-group numbers tell a different story.

This lab uses a pre-trained image classifier and a dataset with demographic labels to run a structured bias audit. You will compute standard classification metrics (accuracy, precision, recall, F1) on the full dataset, then disaggregate those metrics by subgroup to find where the model fails disproportionately. The lab is less about code and more about what the numbers reveal — the same classifier, the same test set, but a completely different conclusion depending on how you slice the results.

Dataset: CelebA Face Attributes

You will use a subset of the CelebA (Celebrity Faces Attributes) dataset loaded via Hugging Face (flwrlabs/celebA). CelebA provides 40 binary attribute labels per image. The notebook defines a TARGET_ATTR variable (default: "Smiling") as the prediction target, and four additional attributes as subgroup slicers: Young, Wearing_Hat, Smiling, Eyeglasses. You can change TARGET_ATTR to any attribute in the list and rerun to audit a different classifier.

  • 2,000 training images for fitting the classifier head, 1,000 test images for the audit.
  • Each image carries 40 binary attribute labels. The notebook uses TARGET_ATTR as the prediction target and other attributes as subgroup slicers.
  • The classifier is MobileNetV2 as a frozen feature extractor, with a logistic regression head trained on the training embeddings and baked into a Keras Dense(1, sigmoid) layer.
  • If the Hugging Face download fails, a cache-clearing cell and alternative loading instructions are included in the notebook.

Part 2: The Demographic Audit

Overall metrics summarize a classifier in one number per dimension. The audit in this section disaggregates those numbers by subgroup and asks: for whom does this model work, and for whom does it fail?

# Cell 4: Per-Group Accuracy by Attribute

What it does: Disaggregates the model's accuracy by subgroups. For each slicing attribute (Young, Wearing_Hat, Smiling, Eyeglasses), computes accuracy, precision, recall, F1, and sample size separately for each subgroup (True vs. False).

Takes in: y_true, y_pred, labels_df, overall_metrics, TARGET_ATTR.

Must produce:

  • slice_attributes: a list of column names used for slicing: ["Young", "Wearing_Hat", "Smiling", "Eyeglasses"].
  • group_metrics: a pandas DataFrame with columns ['attribute', 'group', 'accuracy', 'precision', 'recall', 'f1', 'n_samples']. Each row represents one subgroup (e.g., attribute="Young", group=True, accuracy=0.93, n_samples=612).
  • A grouped bar chart showing accuracy per subgroup for each slicing attribute. Each attribute gets a pair of bars (True vs. False). Include a horizontal dashed line at the overall accuracy for comparison. Print the sample count next to each bar label.
  • Print: the group with the highest accuracy, the group with the lowest accuracy, and the gap between them.

Notes:

  • Some subgroups may be small (e.g., few people wearing hats). If a subgroup has fewer than 20 samples, flag it in the output: "Caution: small sample size."
  • Use zero_division=0 in precision_score, recall_score, and f1_score to handle subgroups where one class may not appear in the predictions.
Reflection. Which subgroup has the lowest accuracy? Is the gap between the best and worst subgroup larger than you expected? What might explain the difference — training-set representation, visual distinctiveness of the attribute, something else? 
# Cell 5: Intersectional Analysis

What it does: Crosses two slicing attributes to create intersectional subgroups and computes per-group accuracy for all four True/False combinations.

Takes in: y_true, y_pred, labels_df.

Must produce:

  • ATTR_A, ATTR_B: two attribute names to cross. Default: "Young" × "Smiling".
  • intersect_metrics: a pandas DataFrame with columns ['attribute_a', 'attribute_b', 'group_a', 'group_b', 'accuracy', 'precision', 'recall', 'f1', 'n_samples']. Four rows (one per combination).
  • A 2×2 heatmap showing accuracy for each intersection. Rows = attribute A (True/False), columns = attribute B (True/False). Annotate each cell with accuracy and sample count.
  • Print: the accuracy gap between the best-performing and worst-performing intersection.

Notes: Intersectional subgroups can be small. If any cell has fewer than 15 samples, note this in the output. The point is to demonstrate that overall accuracy can hide compounding disadvantages — a group that is fine on one attribute and fine on another may still have low accuracy when both co-occur.

Reflection. Did the intersectional analysis reveal a subgroup that performs worse than either individual attribute suggested? This is the core insight of intersectional auditing: combined identities can produce failures that single-attribute analysis misses.

Threshold Sensitivity Analysis

# Threshold Sweep

What it does: The default classification threshold is 0.5. This cell tests what happens to per-group accuracy when you vary the threshold from 0.3 to 0.7.

Takes in: y_true, y_pred_proba, labels_df, group_metrics.

Must produce:

  • thresholds: a numpy array from 0.3 to 0.7 in steps of 0.05.
  • A line plot with three lines: overall accuracy, best subgroup accuracy, and worst subgroup accuracy (from Cell 4). X-axis: threshold. Y-axis: accuracy. Include a vertical dashed line at the default 0.5.
  • Print: the threshold that minimizes the absolute accuracy gap between best and worst subgroups, the gap at that threshold, the gap at 0.5, and the overall accuracy at both thresholds.

Notes: This demonstrates that fairness and accuracy are tunable. A different threshold may reduce the gap between subgroups at the cost of overall accuracy. There is no "correct" threshold — the choice depends on what the deployer values.
