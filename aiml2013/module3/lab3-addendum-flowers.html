Lab 3 Addendum: Try Real Photos

Run the same embedding pipeline on full-resolution images and see what changes.

Why a second dataset?

CIFAR-10 images are 32×32 pixels. When you fed them to MobileNetV2 in the main lab, the model upscaled each image 7× to reach its required 224×224 input. That upscaling blurs details and invents pixels that weren’t in the original photo. The embeddings you computed are based partly on real content and partly on interpolation artifacts.

The TensorFlow Flowers dataset contains five classes of real photographs at natural resolution (typically 200–500 pixels per side). MobileNetV2 downscales these instead of upscaling, preserving genuine texture and shape. Running the same retrieval pipeline on flowers lets you see how much input quality affects embedding behavior.

# Cell A: Load the Flowers dataset

What it does: Downloads the TensorFlow Flowers dataset (five classes: daisy, dandelion, roses, sunflowers, tulips), loads 15 images per class, resizes them to 224×224, and displays a sample grid.

Takes in: Nothing new. Uses tf, np, plt, pathlib already imported in Cell 1.

Must produce:

  • flower_classes: Python list of the five class folder names, sorted alphabetically: ['daisy', 'dandelion', 'roses', 'sunflowers', 'tulips'].
  • F_PER_CLASS: Integer, value 15.
  • flower_images: Numpy array, shape (75, 224, 224, 3), dtype float32, pixel values 0–255. For each class folder, sort the filenames, take the first 15, load each with tf.io.read_file() and tf.image.decode_jpeg(), resize to (224, 224) with tf.image.resize(), and append. Stack into a single array.
  • flower_labels: Python list of 75 integers. flower_labels[i] is the class index (0–4) for flower_images[i].
  • flower_names: Python list of 75 strings. flower_names[i] is the class name for flower_images[i].
  • Dataset download: Use tf.keras.utils.get_file() with the URL https://storage.googleapis.com/download.tensorflow.org/example_images/flower_photos.tgz and untar=True. The result is a directory containing one subfolder per class. Use pathlib.Path to navigate it. There is also a LICENSE.txt file in the directory; skip anything that isn’t a folder.
  • Sample grid: Display a 1×5 grid showing one image per class at 224×224. Title each subplot with the class name. These images should look visibly sharper than the CIFAR-10 samples.

Notes: The download is about 218 MB and takes 10–20 seconds on Colab. It caches after the first run, so re-execution is instant. Some JPEG files in the dataset may fail to decode; wrap the load in a try/except and skip failures. If you end up with fewer than 15 images for a class, print a warning but continue. The flowers are already larger than 224×224, so tf.image.resize() downscales rather than upscales—the opposite of what happened with CIFAR-10.

# Cell C: Flower retrieval

What it does: Runs the same retrieval logic on the flower embeddings. Picks one query per class, displays the query and top 5 matches as an image grid with class labels and cosine scores.

Takes in: flower_embeddings, flower_images, flower_names, flower_labels, F_PER_CLASS (from Cells A–B).

Must produce:

  • find_similar_flower(query_idx, n=5): Same structure as find_similar_image() from the main lab. Extract the query row from flower_embeddings, compute cosine similarity against all 75 embeddings, exclude self, return top n indices and scores.
  • Five query figures: One per class (indices 0, F_PER_CLASS, F_PER_CLASS*2, F_PER_CLASS*3, F_PER_CLASS*4). Each figure: query on the left, 5 matches on the right, with class name and cosine score. Mark same-class matches with ✓ and cross-class with ✗.

Notes: Five flower classes are visually closer to each other than CIFAR-10’s ten classes (all five are flowers). Expect more cross-class retrievals here. That’s the point: embeddings that separated airplanes from frogs with ease now face a harder discrimination task. Pay attention to which flower classes the model confuses and whether the confusion makes visual sense (color? petal shape? background?).
